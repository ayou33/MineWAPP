# AGENTS.md — MineWAPP (SolidJS / TypeScript)

Minimal **SolidJS + Vite + TailwindCSS v4** web application template (extracted from a production mobile-first codebase). File-system routing via `@generouted/solid-router`, Web Worker request layer, headless form engine, and a subsystem-based application core.

## Commands
```bash
pnpm dev                  # Dev server at http://localhost:3000 (scripts/dev.ts → vite --mode main)
pnpm build [test|pre|prod]# Build: vite build + zip-worker + deploy (scripts/build.ts)
pnpm zip-worker           # Minify public/worker/*.js → dist/worker/ (after editing worker scripts)
pnpm lint                 # ESLint
pnpm lint:fix             # Auto-fix ESLint issues
pnpm typecheck            # tsc --noEmit — full-project type check
pnpm preview              # Preview built assets
```

> ⚠ **`pnpm build` deploy step**: `scripts/build.ts` runs `scripts/deploy.ts` only when that file exists — it is currently missing, so the step is skipped with a warning. Add a real deploy script when you need deployment.
>
> ⚠ **Type-check**: run `pnpm typecheck` (`tsc --noEmit`). The previous TS 6.0.2 crash was fixed (see Known Issues); the only remaining error is `Cannot find module 'quill'` when dependencies are not installed (run `pnpm install`).

## Module Anatomy (`src/modules/`)
Every feature lives in `src/modules/<feature>/` with conventions:
```
src/modules/foo/
├── Foo.index.tsx        # page entry – default export is the page component
├── foo.api.ts           # API defs using get/post from @/tools/request ONLY
├── foo.helper.ts        # module-specific helpers (optional)
├── foo.global.ts        # GlobalSubsystem responders (optional, auto-discovered)
├── foo.mock.ts          # dev mock handlers via defineMock (optional, auto-loaded in dev)
├── store/
│   ├── store.ts         # state type + defaults
│   └── actions.ts       # createScopedActions mutations
├── components/          # module-specific components (optional)
└── hooks/               # module-specific hooks (optional)
```
A new module's global state slice must be registered in `src/store/store.config.ts` (`State` type + `initialState`).

## Page ↔ Module Pattern
Pages are **thin wrappers**. They import a module's entry component and pass it as a `ValidComponent` to `ScopedPage`:
```tsx
// src/pages/foo.tsx
import ScopedPage from '@/provider/scopedPage/ScopedPage'
import { AUTH_ROLE } from '@/config'
import Foo from '@/modules/foo/Foo.index'

export default function FooPage () {
  return <ScopedPage scope={AUTH_ROLE.PASSENGER}>{Foo}</ScopedPage>
}
```
**Critical**: `ScopedPage` uses `<Dynamic component={children} />` — children must be a `ValidComponent` function reference, **never JSX** like `<Foo />`.

## Application Singleton (`src/app/`)
`src/app/application.ts` exports the singleton; `AppCore.ts` provides `createApplication()`; every subsystem is a typed property on the instance.
```ts
import application from '@/app/application'
application.role()          // AUTH_ROLE (PASSENGER / GUEST / USER / AUTHED / ADMIN) — reactive
application.locale()        // current locale signal
application.isReady()       // true once all subsystems finished init()
application.context()       // frozen snapshot of runtime context (ua, platform, webId, …)
application.use<T>(name)    // look up a subsystem by name (optional deps, no circular imports)
application.onRole(fn)      // subscribe to role changes (returns unsubscribe)
application.onLocale(fn)    // subscribe to locale changes

// Session (AccountSubsystem)
application.account.current()          // AppUser | null — reactive
application.account.login(userData)    // persist + activate full session
application.account.logout()
application.account.asGuest(partial)   // non-persisted trial session
application.account.loginWith('password', params)  // via registered IAuthStrategy
application.account.hasPermission('edit:post')
```
`AppUser` is an opaque `Record<string, unknown>` — the system only checks whether a session exists. Do **not** add fields to a global `AppUser` interface; read them via `current()?.['field']`.

## Subsystems (`src/app/subsystems/`)
Each subsystem implements `IAppSubsystem` (`name`, optional `priority`, `init?`, `dispose?`). Boot runs in ascending `priority`; ties break on registration order.

| Priority | Subsystem | Responsibility |
|---|---|---|
| -100 | `bridge` | Native JSBridge handshake; sets `isHybrid` / `appVersion` (duck-typed) |
| -50  | `config` | Remote config / feature flags: `get/set/delete/has/snapshot` |
| -10  | `global` | Cross-module responder registry from `*.global.ts` files |
| 0 (default) | `account` / `network` / `report` / `socket` | Session+permissions / connectivity / analytics / WebSocket manager |

**To add a subsystem**: 1) create a class in `src/app/subsystems/` implementing `IAppSubsystem`; 2) add it to `createApplication({…})` in `application.ts`; 3) it becomes `application.<key>` with full type inference. Use `app.use<T>(name)` inside a subsystem to access peers without circular imports.

## Request Layer (`src/tools/request/`)
- **Never** import axios directly. Use `get`/`post`/`receive` factories.
- Requests run through `lunzi/stateFetch` priority queue with optional Web Worker transport.
- Mock system: prefix the URL with `$` and register a handler with `defineMock(path, handler, options)` in a `*.mock.ts` file (dev only).
```ts
export const fetchFoo = get<FooData, FooParams>('/api/foo/data')
export const submitBar = post<Result, BarParams>('/api/bar/submit')
```
`ServerResponse<T>` envelope is parsed by `responseParser`; every non-2xx/business error is re-thrown normalized as `{ data, url, code, message }`.

### Customisation (`src/tools/request/request.config.ts`)
All project-specific request concerns live in **one file** — do not edit the other request files across projects:

| Export | What to customise |
|---|---|
| `ERROR_CODE` | Backend error code catalog (e.g. `TOKEN_EXPIRED: '00009'`) |
| `ServerResponse<T>` | API response envelope shape (`success/data` vs `code/msg/result`) |
| `Pagination` | Pagination field names (`pageNum/pageSize` vs `page/limit`) |
| `ApiPath` | URL path prefixes your backend exposes (`/api/…`, `/v2/…`) |
| `buildCommonParams` | Fields merged into every request (token, device ID, market, HMAC…) |
| `responseParser` | Unwrap responses, handle global error codes (token expiry, bans…) |

`index.ts`, `request.axios.ts`, and `request.worker.ts` import from `request.config.ts` and must not be edited for project-specific concerns.

## ScopedPage (`src/provider/scopedPage/ScopedPage.tsx`)
Wraps every page. Auto-cancels in-flight requests, toasts, and popups on unmount. Namespaces `on`/`emit` events to the page lifecycle.

```tsx
// src/pages/foo.tsx
export default function FooPage () {
  return <ScopedPage scope={AUTH_ROLE.PRIVATE} pageCode="foo">{Foo}</ScopedPage>
}
```
Props:
- `scope` — `AUTH_ROLE` level (default: `PASSENGER`). Delegated to `PageGuard`.
- `pageCode` — reserved tag (currently unused by the implementation).
- `children` — must be a `ValidComponent` function reference (not JSX).

Context available inside the page component via `usePageContext()`:
```tsx
const { request, toast, popup, interval, delay, on, emit } = usePageContext()
const [fetchData, loading] = request(fetchFoo)
```
`on`/`emit` are namespaced per page instance — events do not leak across pages. Outside a `ScopedPage`, `usePageContext()` falls back to global `toast`/`popup`/`request`/`timer`.

### PageGuard (`src/provider/scopedPage/PageGuard.tsx`)
Embedded inside `ScopedPage`. Handles route-level access control reactively:
- `role < AUTH_ROLE.USER && scope >= AUTH_ROLE.USER` → redirects to `AUTH_PATH` (`/auth`).
- `role >= USER && role < scope() && scope >= AUTHED` → inline 403 screen.

Guard logic uses `application.role()` (a reactive signal) — re-evaluates on login/logout without a page reload.

## State Management (`src/store/`)
```ts
// Read (reactive memo):
const name = useSelector(s => s.user.name)
// Write (action):
actions.setName('Alice')
// Define action:
const actions = createScopedActions('user', {
  setName(set, name: string) { set('name', name) }

```

```ts

export type State = {
  user: { id: string | number | null; name: string; avatar: string }
  cart: { items: CartItem[]; total: number }   // ← add new slice here
}
export const initialState: State = {
  user: { id: null, name: '', avatar: '' },
  cart: { items: [], total: 0 },               // ← and its default value
}
```

## Global Events (`src/common/event.ts` + `src/config/keys.ts`)
```ts
import { on, off, emit } from '@/common/event'
on(EVENTS.LOGIN, handler)
off(EVENTS.LOGIN)
```
Thin wrapper over `lunzi/useEvent`. Event names live in `EVENTS` (`src/config/keys.ts`): core `LOGIN/LOGOUT/TOKEN_ERROR/WAKEUP` (do not rename) + project `CONSUME/BALANCE_CHANGED`. Page-scoped `on`/`emit` in `ScopedPage` auto-namespace to avoid cross-page leaks.

## Styling Rules

### TailwindCSS v4 — `.css` files only
TailwindCSS v4 uses `@tailwindcss/vite` plugin which **only processes `.css` files**. Never `@import "tailwindcss"` inside SCSS.
- `src/style/tailwind.css` — TailwindCSS entry with `@theme` / `@theme inline` blocks. Must remain `.css`.
- Use `@theme` to expose CSS variables as Tailwind utilities; `@theme inline` maps semantic `--c-*` tokens.
- Use the semantic z-index scale (`z-focus`, `z-overlay`, `z-sticky`, `z-float`, `z-backdrop`, `z-drawer`, `z-popup`, `z-dropdown`, `z-toast`, `z-system`) — do **not** use raw `z-[N]` in modules.

### SCSS — custom styles only
- `src/style/var.scss` — MD3-aligned design tokens (`--md-*` roles, `--c-*` semantic tokens) + motion (`--transition-duration`, `--ease-*`).
- `src/style/transition.scss` — All animation classes (tip animations, popup transitions). Uses CSS variables, **not SCSS variables**, for duration and easing.
- `src/style/index.scss` — `@use "./var.scss"` + `@use "./transition.scss"` (note: `@use`, not `@import`), base reset, HarmonyOS fonts, hidden scrollbars.
- Dark mode: add class `dark` to `<html>`; `--c-*` tokens re-map under `.dark`.

### Component Styles — Tailwind First
**Always use Tailwind utility classes in JSX** for component styling. Do not create `*.module.scss` or `*.module.css` for component-scoped styles unless truly unavoidable.

Permitted exceptions (use `*.module.css`, never `.scss`):
- Keyframe animations (`@keyframes`)
- Complex pseudo-element selectors (`::before`/`::after`) when Tailwind pseudo-utilities are insufficient
- Third-party integration overrides (e.g. `richtext.css` for Quill)

When a module file is required, keep it minimal — only what Tailwind cannot express.

### CSS Variables
All shared timing/easing values live as CSS custom properties in `var.scss`:
```scss
:root {
  --transition-duration: 500ms;
  --ease-back-in-out: cubic-bezier(0.68, -0.25, 0.2, 1.2);
}
```
Read them in TypeScript via `getComputedStyle(document.documentElement).getPropertyValue('--transition-duration')`.

## Animation Conventions

### Tips (toasts)
Self-managed animation in `Tip.tsx` via CSS class toggling — **no `<Transition>` wrapper**. `<Transition>` inside `<For>` breaks exit animations because `<For>` destroys DOM before `<Transition>` can animate.
- Three position-specific classes: `.tip-slide-down` (TOP), `.tip-scale` (CENTER), `.tip-slide-up` (BOTTOM).
- Enter: toggle `.tip-visible` after double-`requestAnimationFrame`.
- Exit: remove `.tip-visible`, delay removal by `--transition-duration`.
- Swipe-to-dismiss only for TOP position.

### Popups
Use `<TransitionGroup>` from `solid-transition-group` for list-based enter/exit.
`forceRemove` is a pure teardown timeout based on `--transition-duration` + safety margin — it never manipulates the closing array directly.

## Form System (`src/features/form/`)
Headless reactive form engine:
- `types.ts` — `Rule`, `FormConfig`, `CascadeContext`, `Relation`, `FieldMeta`, `ValidateOn`
- `rules.ts` — Built-in validators: `required`, `minLength`, `maxLength`, `min`, `max`, `pattern`, `email`, `match`, `oneOf`, `custom`
- `createForm.ts` — Reactive stores, cascade with loop protection, relation effects, bind helpers (`bind`, `bindNumber`, `bindCheckbox`, `bindSelect`), `validate`/`submit`/`reset`
```ts
const form = createForm({
  initialValues: { name: '', age: 0, agree: false },
  rules: { name: [required('请输入姓名'), maxLength(30)] },
  validateOn: 'blur', // 'change' | 'blur' | 'submit'
})
// <Input {...form.bind('name')} />   <Input {...form.bindNumber('age')} />
form.isValid(); form.isDirty(); form.isSubmitting()
await form.submit(values => { … })
```

## Table Feature (`src/features/table/`)
Client/server-side data table with sorting, filtering, multi-select, grouping, column pinning/visibility/resizing, and expandable rows.
```tsx
const table = createTable({
  columns: [
    { key: 'name', title: '姓名', sortable: true, filterable: true },
    { key: 'actions', title: '', isAction: true, render: (_, row) => <ActionBtns row={row} /> },

  rowKey: r => r.id,

return <Table table={table} expandable={{ onToggle, isExpanded, renderContent }} />
```

Files: `createTable.ts` (state engine), `Table.tsx` (render + resize/pin), `Table.menu.tsx` (header menus), `Table.ui.tsx` (pagination/icons/checkbox), `Table.helpers.ts` (width math), `types.ts`.
> ⚠ Table UI strings are currently **hardcoded Chinese** (`暂无数据`, `共 X 条`, `固定此列`, …) — should be routed through `t()`.

## RichText (`src/features/richtext/`)
`RichTextEditor.tsx` — Quill 2 based, integrates with `createForm` and MD3 tokens. Controlled `value`/`onChange`; `dangerouslyPasteHTML` sync guarded by a `userEditing` flag; `disabled`, `error`, `minHeight` props. Styles in `richtext.css` (third-party override exception).

## i18n (`src/features/i18n/`)
- `t(path, args?, dft?)` — translate; `I18n` component (`I18n.p/.div/.button/.span`) for JSX use.
- Dictionaries loaded from `public/lang/*.json`; `loadLang` at app boot; `setLocale` persists + reloads.
- `config.ts` — `Dictionary`, `Locale`, `templateResolver` (supports `{{var}}` and `colorful` `<1>…</1>` spans).
- **Always route user-visible strings through `t()`** — components in `features/table`, `components/popups`, `components/DateTimePicker`, `components/loading` still contain hardcoded Chinese.

## A/B Test System (`src/features/abTest/`)
Group-based feature flag system for conditional rendering and lazy loading.

| File | Purpose |
|---|---|
| `ABTest.tsx` | Main component — renders children/fallback based on `ifFeatureAllowed` (core, do not edit) |
| `Alternative.tsx` | Lazy-loads a component via dynamic import, switches between `default`/`fallback` exports by an `Accessor<boolean>` predicate (core) |
| `FeatureAlternative.tsx` | Convenience wrapper — lazy-loads a module and renders `default`/`fallback` based on `ifFeatureAllowed` |
| `abTest.engine.ts` | Core engine: `FeatureControl` type, `compareVersion`, `compatible` (core, do not edit) |
| `feature.config.ts` | **Project config**: `Feature` enum, `ControlledFeatures` rules, `platformContext` bridge wiring |

**Usage — static children:**
```tsx
import ABTest from '@/features/abTest/ABTest'
import { Feature } from '@/features/abTest/feature.config'

<ABTest feature={Feature.A} fallback={<OldUI />}>
  <NewUI />
</ABTest>
```

**Usage — lazy/dynamic load:**
```tsx
<ABTest
  feature={Feature.A}
  load={() => import('./MyFeature')}  // module must export default + optional fallback
/>
```

**Feature configuration** (`feature.config.ts`):
```ts
export enum Feature {
  NEW_CHECKOUT = 'new_checkout',
}

export const ControlledFeatures: Partial<Record<Feature, FeatureControl>> = {
  [Feature.NEW_CHECKOUT]: {
    groups: [1, 2],          // only users in these groups see the feature
    versions: { ios: '2.0.0', android: '2.0.0', web: true },
  },
}

// Wire to your native bridge here (Capacitor, JSBridge, etc.)
export const platformContext: PlatformContext = {
  appVersion: '9.9.9',
  isApp: false,
  isIOSApp: false,
  isAndroidApp: false,
}
```
- `groups`: if omitted, all authenticated users qualify.
- `versions`: version-gate for native app builds; `web: true` enables on web.
- `ifFeatureAllowed(feature, userGroup)` checks **both** group and platform/version gates.
- Add new features to the `Feature` enum and optionally to `ControlledFeatures`.
- `sample-feature.ts` is superseded by `feature.config.ts` + `abTest.engine.ts` and can be deleted.

## KeepAlive / LoadMore / PageTransition
- **KeepAlive** (`src/features/keepAlive/`) — route-level component caching (LRU, max 10). `<KeepAlive id="…">` caches children in a root; `useActivated`/`useDeactivated` hooks; cache cleared on `EVENTS.LOGOUT`.
- **useLoadMore** (`src/features/loadMore/`) — infinite scroll: `const [loaded, actions, states] = useLoadMore(request, mix, pageSize)` with `refresh/retry/loadMore/loadPage/patch/patchAll` and `ifIdle` guards.
- **PageTransition** (`src/features/pageTransition/`) — `useForwardNavigate` + `ForwardA` set `state.forward` so forward navigations can animate. `useBack()` in `hooks/` returns via `location.state.from` or `history.back()`.

## Coding Conventions
- Alias: `@` → `src/`, `/^lunzi/` → `./lunzi` directory.
- Functional components only. No class components.
- Prefer Tailwind utility classes in JSX over module CSS. Use `*.module.css` only for keyframes, pseudo-elements, or selectors Tailwind cannot express.
- Prefer small, focused changes over broad refactors.
- Route all user-visible strings through `t()` / `I18n` — do not hardcode Chinese/English literals in components.
- `<button>` elements that are not form-submits should set `type="button"` explicitly (buttons default to `submit` inside forms).
- Always verify build (`pnpm exec vite build`) and type-check (`pnpm typecheck`) after structural changes.

## High-Risk Areas (Be Conservative)
- Auth / token / session lifecycle (`AccountSubsystem`, `PageGuard`, `responseParser` token-expiry path).
- ScopedPage cleanup and request cancellation (`useRequest` label-based cancel, `cancelToasts`/`cancelPopups`).
- Animation timing — changes to `--transition-duration` or `--ease-*` affect tips, popups, and page transitions globally.
- `lunzi/` submodule — run `pnpm zip-worker` after any worker changes; never edit submodule files in this repo.
